# Configuration schemas

Run `go generate -run generate-config-schema` from the repository root to update
`actionlint.schema.json`. Actionlint owns tool selection, enablement, and the union
of a configuration path and inline settings. `tools` lists one entry per bundled
provider manifest under `internal/tools/provider/bundled`; each manifest's
`config_schema` describes inline `config` settings and its `config_shorthands`
appear beside the host keys. A `config_schema` equal to a snapshot under
`schemas/<name>/` is referenced with a `$ref` relative to the main schema's
location, as the ShellCheck directives reference `schemas/shellcheck/0.11.0.schema.json`;
any other schema is embedded.
The root and tool schemas omit `$id` so their retrieval location determines reference resolution.
An installed npm package uses its bundled schema; a versioned CDN URL or Git
commit URL uses the schema from that same release or revision.

Generation requires `dprint` on `PATH`. The generator formats its output through
`dprint fmt --stdin` using the repository configuration before writing the file.
The formatting test compares generated bytes with the committed schema and checks idempotence.

The version identifies the ShellCheck directive contract represented by the YAML
mapping. Actionlint maintains this schema. Users can select their installed
ShellCheck version independently.
Runtime configuration parsing does not download schemas. Tests check relative
resolution for local packages, CDN releases and Git revisions with external
loading disabled.

## Ruff definitions

The host schema describes tool selection, enablement, and the shape of the Ruff
wrapper. It leaves rule selectors, target versions, preview behavior, and the
contents of `config` to the selected engine. For native analysis, the Ruff
executable validates the options. WebAssembly engines expose `validate_config` for this.
The engine's metadata carries its configuration schema.

The root schema provides small completion examples without constraining settings
to one bundled Ruff release. Tests exercise base and override settings through
the parser, JSON Schema validator, and the real YAML language service offline.
Run `npm ci` first for the language-service test.

`schemas/ruff` archives published Ruff snapshots; configuration decoding and schema
generation use the selected engine's schema instead.

## Updating ShellCheck support

When a future ShellCheck version adds configuration directives:

1. Update the native directive type and parser.
2. Change `shellcheckSchemaVersion` in `main.go` to that ShellCheck version.
3. Run `go run ./tools/config -init-shellcheck-schema` from the
   repository root to create the new snapshot. This command refuses to overwrite
   an existing version.
4. Copy the new snapshot into the bundled ShellCheck manifest's `config_schema`;
   configuration decoding validates inline settings against it.
5. Regenerate the root schema and run this package's tests. Both generators format
   their output before writing it.
6. Keep all previously published version files and URLs available.

Normal generation never rewrites the versioned snapshots. The snapshot test
detects drift between the current directive type and the selected version.
Corrections to descriptions or to an inaccurate existing contract require an
explicit edit and review; do not replace an old snapshot with a newer contract.

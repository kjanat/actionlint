# Workflow schema audit

Audited 2026-09-13. This inventory covers every definition in both workflow schemas, including root/job structures, nested structures, enum leaves, and runner compatibility variants. Expression context/function behavior is covered separately by the context audit.

## Sources

- [Runner workflow schema](https://github.com/actions/runner/blob/759385a3510197a58b5c08dc1f373b74b9f4643b/src/Sdk/WorkflowParser/workflow-v1.0.json), commit `759385a3510197a58b5c08dc1f373b74b9f4643b`.
- [Language Services workflow schema](https://github.com/actions/languageservices/blob/4043eda158e16579cc5fb1b0b07a4bce2a76f0b5/workflow-parser/src/workflow-v1.0.json), commit `4043eda158e16579cc5fb1b0b07a4bce2a76f0b5`.
- [Workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax) and [workflow triggers](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows), retrieved 2026-09-13.

The schemas disagree. Language Services carries newer public fields; runner has internal/relaxed roots and several older definitions. Schema acceptance also omits semantic checks performed by the service. This audit preserves documented linter checks and records these differences explicitly.

## Retained differences and limits

- Empty mappings/sequences: actionlint intentionally diagnoses unnecessary empty `env`, `defaults`, `outputs`, `services`, `with`, `strategy`, matrix rows/filters and steps, although schema primitives admit many of these. See [documented empty-section checks](checks.md#check-empty-mapping). Empty permissions remains valid. These diagnostics enforce linter policy beyond GitHub schema validation.
- Required image/credentials: parser requires image and both username/password for explicit credential mappings; schema mapping properties omit required markers. These checks prevent unusable configurations. Empty service image is a specific documented exception.
- Empty executable/environment/output strings: actionlint retains semantic nonempty checks for script bodies, environment names/URLs, workflow output values and several optional configuration strings even where schemas use `string`. The table exposes their source types; this audit does not claim complete acceptance equivalence for empty/no-op configurations.
- Dynamic mapping objects: matrix, env, services, credentials, containers, strategy, job defaults.run, step with, runner selection, concurrency, environment and snapshot accept their inherited expression contexts. Job outputs and reusable caller with/secrets have contexts only on their values; their mapping structures correctly remain static. Arbitrary runtime object values retain unknown types until their contents can be established.
- Literal null mapping values: the parser's general empty-section behavior accepts null as an omitted mapping in some optional input/secret/output sections. Strict schemas distinguish explicit null unions from plain mappings. Existing coercion and empty-section policy remains; scalar resolution is documented in the context report.
- Legacy events: `project`, `project_card`, `project_column` remain in schemas after removal from current trigger documentation. `pull_request_comment` is documented as "use issue_comment". The generated public trigger inventory retains current documented event tables and diagnoses these legacy aliases/events. Runner internal `dynamic`, `interactive_component`, and `member` are also outside the public trigger set.
- Runner relaxed schemas: `on`, `on-new`, relaxed dispatch/event maps and unconstrained `any` nodes exist for compatibility/internal parsing. actionlint applies its public syntax/semantic checks; unknown keys/events are not accepted merely because a relaxed runner root allows them.
- Upstream schema defects/drift: Language Services `repository-dispatch-string` has constant `branch_protection_rule`; actionlint correctly recognizes `repository_dispatch`. Runner is older for new permissions, queue, deployment, timezone, parallel/background steps, choice empty strings, merge-group branch filters, and recent activity enums. Existing `merge_group: destroyed` support comes from webhook documentation although strict schemas omit it.
- `wait-all: false` remains a no-op lint diagnostic. Language Services `step-wait-all-value` admits null/boolean with no expression context; the parser now rejects expressions that it previously accepted and discarded. [Current wait-all documentation](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#jobsjob_idstepswait-all) describes an argument-free step that always runs. No supported dynamic expression form was found.
- Timezone is schema nonempty-string; actionlint validates IANA timezone names. The erroneous rejection of `UTC` is fixed: [IANA backward links](https://data.iana.org/time-zones/tzdb/backward) explicitly map `UTC` to `Etc/UTC`. `Local` remains rejected because it is a Go host-local selector outside the IANA database. Aliases and ordinary region names have regression coverage.
- These are source and local-fixture results. No workflows were dispatched to GitHub and no claim of complete runtime equivalence is made.

# actionlint v2.0.0 release notes

## What changes

v2 adds independently installed Wasm analyzers, typed script engines and runner
providers. Project configuration declares dependencies; the adjacent lockfile
records exact registry versions and artifact digests. ShellCheck and Ruff are the
default plugins for new configurations and eligible legacy migrations. Native
backends remain available when explicitly selected.

The CLI also adds a language server, revision-checked fixes, typed JSON results,
and action-manifest discovery. Unreferenced local actions are checked alongside
workflows, so an upgrade can reveal findings outside files previously checked.
See the [changelog](../../CHANGELOG.md) for the complete change list.

## Migrate configuration and plugin dependencies

Preview the selected file, then apply the migration:

```sh
actionlint config migrate --config .github/actionlint.yaml
actionlint config migrate --config .github/actionlint.yaml --write
actionlint check
```

Use `actionlint config init` for a project without configuration. Local CLI and
JavaScript Action checking also migrate a selected legacy file before plugin
selection. Review and commit that change before relying on it in CI.

Migration moves old root settings into `lint.rules`, preserving knowledge such as
self-hosted labels and configured variable/secret names. Old policy `false`
settings become explicit `off` levels, which now survive presets and `--strict`.
Conflicting old and new settings produce an error instead of choosing silently.
YAML, JSON and TOML retain their format where the conversion can preserve meaning.
See [configuration migration](../config-migration.md) for every mapped setting.

When `plugins` was omitted, initialization or an explicit migration installs the
applicable defaults:

```yaml
plugins:
  - shellcheck
  - ruff
```

These names are assigned by the registry, not inferred from repository names.
Existing plugin lists, `plugins: []` and `plugins: null` remain explicit choices.
Disabled tools and explicit native backends keep their selection; ShellCheck
settings requiring native rc/source access or disabled-code ranges retain the
native backend. The isolated Wasm component no longer follows source files
implicitly. Supply a native executable yourself when selecting those features.
A canonical configuration is not automatically enrolled merely because it lacks
`plugins`.

Applying a migration downloads and verifies dependencies before saving configuration and
lockfile; download failure leaves both project files unchanged. Preview and
`--check` do not download. Inherited files are normalized when read; select each
file explicitly to rewrite its syntax on disk.

Commit both `.github/actionlint.yaml` and the adjacent
`.github/actionlint.plugins.lock.json`. The declaration can select a version or
allow `latest`; the lock still records exact bytes. Normal checking restores
missing locked artifacts and never upgrades them. `actionlint plugin update`
explicitly resolves updates; `actionlint plugin sync` restores pins and refreshes
registry withdrawal information. A populated, verified cache works offline.

You can also declare a directly hosted artifact:

```yaml
plugins:
  - "https://example.org/check.wasm#sha256=<64-hex-digit-digest>"
```

Replace the URL and digest before use. The digest identifies the downloaded
bytes, including compression. Direct URLs require the pin and do not need a lock
row; a project containing only direct URLs creates no registry lockfile. Registry
withdrawal policy cannot revoke independently hosted URLs.

Registry-deprecated releases remain usable with warnings. Withdrawal prevents
new resolution while existing locks can continue with a warning. Known revoked
digests are refused even from cache. Offline checking uses previously refreshed
status; it cannot discover a new revocation without a successful refresh.
See [plugin management](../plugins.md#install-from-the-registry).

## Update GitHub Actions

The JavaScript Action loads the same project declarations and locked plugins as
the CLI. It does not install Ruff or ShellCheck on `PATH`. Commit the migrated
configuration and lockfile before running the upgraded Action.

`plugin-cache` defaults to `true`. The Action restores only selected artifacts,
keys the cache by operating system and exact digests, and rehashes every restored
file. It saves verified downloads even when linting finds errors. Cache service
failures warn and fall back to ordinary downloads. Set `plugin-cache: false` to
disable caching. Compiled runtime state is not included.

`install-only` installs the host binary and requires `add-actionlint-to-path`;
it does not provision native script linters. For machine consumers, Action JSON
now contains a result object with `diagnostics`. Diagnostic fields use `rule`,
`path`, `start` and `end`, with exclusive end positions. Update integrations using
the [result migration guide](../results.md#migration).

## Move pre-commit to its dedicated repository

Change the repository URL explicitly. `pre-commit autoupdate` cannot move a hook
between repositories:

```yaml
repos:
  - repo: https://github.com/kjanat/actionlint-pre-commit
    rev: v2.0.0
    hooks:
      - id: actionlint
```

The hook tag is published after verification of the host release, its binary
wheels and container image.

Replace `actionlint-shellcheck` and `actionlint-bundled` with `actionlint` and the
project's Wasm plugin declarations. Remove Go `additional_dependencies` used for
native ShellCheck. The default hook installs the exact native host wheel in its
Python environment. System and Docker alternatives remain available; the released
Docker hook pins the verified image digest.

Run `pre-commit install` and `pre-commit run actionlint --all-files` after migration.
Hooks check all repository workflows on every commit, including deletion-only
changes to local actions or reusable workflows. Existing immutable v1 hook
revisions remain at the old URL. See [hook migration](../migration-v2.md).

## Update Go installations and integrations

The major-version module path is `actionlint.kjanat.dev/v2`:

```sh
go install actionlint.kjanat.dev/v2/cmd/actionlint@v2.0.0
```

Source builds require Go 1.27 or later. Binary distributions do not require a Go
toolchain.

Library consumers must update imports to `/v2` and migrate from the former flat
root API to the `analysis`, `analyzer`, `config`, `diagnostic`, `document`, `rule`,
`source` and `syntax` packages. Use `analysis.Files` or `analysis.Repository` for
file discovery and configuration selection. Check both returned findings and
errors: incomplete analysis can still produce useful diagnostics.
See the [Go API migration](../api.md#migration-from-the-flat-api).

## Plugin authors

The typed WIT interfaces separate document analyzers, snippet engines and runner
knowledge providers. Ruff uses the script-engine component interface; existing
core engines keep their version-1 JSON ABI. Analyzer-only and provider-only
components need implement only their own role. Installing a runner provider does
not change the execution target: select it explicitly.

Runner checks and dependent execution inference share resolved provider knowledge.
Unknown, stale or incomplete evidence cannot prove that a runner label is invalid.
Provider failures remain analysis failures rather than invented runner facts.

The host validates artifact metadata, interface support, options and resource
limits. Registry admission alone does not prove compatibility with every host.
See [plugin authoring and interfaces](../plugins.md) for WIT files, examples and
test commands. Runny and actup integrations are not part of this release.

actionlint 1.16.0 adds more accurate checks for action metadata and matrices, optional timeout and permissions policies, and the configuration schema in the npm package. The new policies are opt-in; the correctness checks apply automatically.

## Set timeout bounds and require explicit permissions

You can now require job timeouts to fall within a range. Add this to `.github/actionlint.yaml`:

```yaml
policy:
  require-job-timeout: {min-minutes: 5, max-minutes: 60}
  require-permissions: {scope: job}
```

The timeout policy accepts literal values from 5 through 60 minutes, including both endpoints. Either bound can be omitted. Invalid ranges are rejected when the configuration loads. Expression values cannot be evaluated statically, and jobs calling reusable workflows do not take a caller-side timeout.

The permissions policy requires every job to declare its token permissions, including jobs calling reusable workflows. For example:

```yaml
on: push
jobs:
  check:
    runs-on: ubuntu-latest
    permissions: {}
    timeout-minutes: 15
    steps:
      - run: echo 'No repository API access needed'
```

An empty mapping satisfies the policy. Grant the specific permissions a job needs; this check requires an explicit decision but does not determine whether those grants are minimal. Use `require-permissions: true` to require a workflow-level declaration instead.

Go callers can configure timeout bounds with `RequireJobTimeoutRange`. See [configuration documentation](https://github.com/kjanat/actionlint/blob/v1.16.0/docs/config.md). Related: kjanat/actionlint#55, kjanat/actionlint#83, rhysd/actionlint#728.

## Catch more errors inside local actions

Action metadata checks now derive available contexts, composite step keys, and special-function rules from GitHub's runner schema. This expands the input-default checks contributed by @johnament in kjanat/actionlint#131 and his earlier composite expression checks in kjanat/actionlint#124 (rhysd/actionlint#46).

For example, a referenced local action cannot read `env` in an input default:

```yaml
name: Example
description: Demonstrate an unavailable input-default context
inputs:
  mode:
    default: ${{ env.BUILD_MODE }}
runs:
  using: composite
  steps:
    - run: echo ready
      shell: bash
```

actionlint now points at that default in the action's metadata. Pass the value through the workflow's `with` mapping, or use a static default. These checks also cover JavaScript and Docker action defaults, plus composite `shell`, `continue-on-error`, and whole `with`/`env` expressions. Special functions are checked for availability and argument counts.

The generated rules ship with the binary. Linting does not download the runner schema or fetch arbitrary remote actions.

## Distinguish deprecated runtimes from invalid metadata

Runtime data now comes from GitHub's runner source, including the accepted `runs.using` values, which runtimes remain bundled, and their deprecation status. For local actions and actions in the built-in popular-action database, `node20` produces a deprecation diagnostic while input and output validation continues.

```yaml
runs:
  using: node20
  main: index.js
```

Action maintainers should migrate this declaration and their code to `node24`. The data included in this release records GitHub's announced Node 20 removal date as September 23, 2026. Removed runtimes and unrecognized metadata values receive distinct diagnostics. Repository generation and weekly Upkeep refresh this data for subsequent releases.

## Matrix checks follow YAML types and expansion order

Quoted numbers now remain distinct from numeric values during matrix comparisons, while equivalent numeric spellings compare equally. Diagnostics preserve that distinction, making exclusions easier to correct. Related: kjanat/actionlint#57.

Exclusions are checked against the original matrix because GitHub processes `exclude` before `include`. This example now reports that `windows-latest` is absent from the original `os` row:

```yaml
strategy:
  matrix:
    os: [ubuntu-latest]
    include:
      - os: windows-latest
    exclude:
      - os: windows-latest
```

The later `include` cannot make that exclusion valid. Remove the unnecessary exclusion, or change the original matrix to match the combinations you intend to run. Thanks @muzimuzhi for rhysd/actionlint#634.

## Use the npm package's configuration schema

`@kjanat/actionlint` now contains `actionlint.schema.json` and exposes it through the `./schema` package export. Every platform package also exports its own `./package.json`. Related: kjanat/actionlint#136.

For an editor or tool that accepts a schema URL, copy:

```text
https://cdn.jsdelivr.net/npm/@kjanat/actionlint@1.16.0/actionlint.schema.json
```

Or add the YAML language-server directive to your configuration:

```yaml
# yaml-language-server: $schema=https://cdn.jsdelivr.net/npm/@kjanat/actionlint@1.16.0/actionlint.schema.json
```

Pinning the URL keeps editor validation aligned with the actionlint version you run. The schema includes the new policy settings.

## Other fixes and release improvements

- YAML anchors and aliases containing `+` are rejected, matching GitHub Actions' accepted syntax. kjanat/actionlint#114.
- `required-actions` errors point at the first job with its own steps when an earlier job calls a reusable workflow. kjanat/actionlint#54.
- `windows-11-arm` may overlap `windows-11-vs2026-arm` during the announced Visual Studio 2026 migration. Incompatible image combinations still produce diagnostics. kjanat/actionlint#126.
- The Playground derives its version badge and documentation links from Git during the build and redeploys after successful releases. The label identifies the code it runs, and release bumps no longer edit its HTML. kjanat/actionlint#144.
- npm trusted publishing uses OIDC for the launcher, platform packages, and changelog package. Workflow filenames and publisher configuration now consistently use `.yml`.
- Pandoc installation in CI retries failed GitHub release requests, replaces partial downloads, and still verifies assets before installation. kjanat/actionlint#138.

v1.10.0 makes the fork directly installable through its own Go module path. Its main benefit is choosing the maintained fork explicitly when installing the command or embedding the Go library; it does not introduce a new set of workflow checks.

## Install this fork through Go

For this release, the module moves from `github.com/rhysd/actionlint` to `github.com/kjanat/actionlint`:

```sh
go install github.com/kjanat/actionlint/cmd/actionlint@v1.10.0
```

Library consumers selecting this release should use:

```go
import "github.com/kjanat/actionlint"
```

The executable remains named `actionlint`. The module path determines which project's implementation is installed, so using the upstream import path would not select this fork.

**Historical migration:** v1.12.0 subsequently moves the module to `actionlint.kjanat.dev`. The commands above document the v1.10.0 release; use the [current installation guide](https://github.com/kjanat/actionlint/blob/master/docs/install.md) when installing a current version.

## Keep examples and release checks usable

The README workflow example now uses the then-current major releases of `actions/checkout`, `actions/setup-node`, and `actions/cache`, so the introductory example better matches supported workflows.

The download script's CI checks now distinguish a branch build from a published release: branch builds resolve the latest available release, and the pinned release version is tested after its assets have been uploaded. Missing assets cause a clean failure. This avoids making ordinary development depend on downloading a version that has not been published yet.

If you already use the v1.9.0 archive, expect the same linting features. This release is most useful for Go-based installation and library consumers moving to the fork.

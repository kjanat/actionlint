v1.13.0 adds optional repository policies alongside the existing correctness checks. It also checks secrets and permissions passed to local reusable workflows, validates composite action steps, corrects matrix value types, and provides shell completions.

## Choose the conventions your repository enforces

Add a `policy` mapping to `.github/actionlint.yaml` to enable the checks you want:

```yaml
policy:
  require-commit-hash: true
  require-job-timeout: {max-minutes: 30}
  required-actions: [actions/checkout]
```

With this configuration:

- Remote action and reusable-workflow references must use a full commit hash. `docker://` images need a digest. Tags such as `actions/checkout@v7` are reported; local references and dynamically constructed `uses` values are skipped.
- Jobs with their own steps must declare `timeout-minutes`, and literal timeouts above 30 are reported. Jobs calling reusable workflows are skipped because they cannot set that key on the call.
- Workflows with their own steps must use `actions/checkout`. The policy searches the steps written in that workflow, without following calls into other actions or workflows. Required-action entries support glob patterns for the action name and ref.

These are opt-in conventions. They remain off unless configured, while correctness checks continue to run normally. Related: kjanat/actionlint#39.

Thanks @mortenson, @jmeickle-theaiinstitute, and @perryd01 for the commit-pinning work and requests (rhysd/actionlint#436, rhysd/actionlint#435, rhysd/actionlint#524; kjanat/actionlint#40); @TomNorth for timeout policy work (rhysd/actionlint#581; kjanat/actionlint#44); and @chrisreddington for the required-actions idea (rhysd/actionlint#469, rhysd/actionlint#474; kjanat/actionlint#43).

## Catch misspelled secrets and insufficient workflow permissions

Declare the repository secrets your workflows may reference:

```yaml
config-secrets:
  - DEPLOY_TOKEN
  - API_KEY
```

Names are checked case-insensitively, so a misspelling such as `secrets.DEPLOY_TOKNE` is reported. Built-in secrets (`GITHUB_TOKEN`, `ACTIONS_STEP_DEBUG`, and `ACTIONS_RUNNER_DEBUG`) and secrets declared by `workflow_call` remain allowed. Leaving the list unset disables this check. Thanks @tdeo for rhysd/actionlint#649; implementation: kjanat/actionlint#42.

Calls to local reusable workflows now check the permissions the caller grants against what the called workflow requires. For example, a caller granting only `contents: read` cannot satisfy a callee that needs `contents: write`.

Use `assume-default-permissions: restricted` or `permissive` to model the repository's default token permissions when the caller declares none. OIDC's `id-token` permission still requires an explicit grant. Metadata loading also resolves YAML aliases and accepts unused anchors, so anchored callee definitions can be checked. Thanks @SeriousBug and @ianlewis (rhysd/actionlint#670, rhysd/actionlint#552; kjanat/actionlint#41).

## Preserve matrix value types

Quoted numbers are strings. This now produces a type error because `timeout-minutes` requires a number:

```yaml
on: push
jobs:
  build:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        minutes: ["10"]
    timeout-minutes: ${{ matrix.minutes }}
    steps:
      - run: echo ready
```

Use `minutes: [10]` when the value is meant to be numeric. Quoting is still appropriate for version strings, which should not be treated as numbers.

The checker follows YAML 1.2 scalar resolution, preserves explicit string and block-scalar types, and rejects invalid or unsupported explicit tags. Values such as `0b10`, `-0x10`, and `1_000` remain strings under the rules GitHub uses. Existing workflows that relied on the earlier type inference may therefore gain a useful diagnostic. Thanks @hdimer and @altendky (rhysd/actionlint#727, rhysd/actionlint#250; kjanat/actionlint#38).

## Validate the shape of composite actions

Referenced local composite actions now have their `runs.steps` entries checked. A script step needs both `run` and `shell`; an action step needs `uses`. Mixing those forms, using unsupported keys, supplying null or non-string values, leaving `uses` empty, or calling a reusable workflow from a composite step is reported.

```yaml
name: Example
description: A composite action with an incomplete script step
runs:
  using: composite
  steps:
    - run: echo ready
```

Add `shell: bash` to this step. The error points at the action metadata file, making it clear where the fix belongs. Thanks @stefreak for rhysd/actionlint#277; implementation: kjanat/actionlint#70. This release checks step structure; expression-context checking arrives in later releases.

## Get shell completions and ShellCheck in pre-commit

Generate completions for Bash, Zsh, Fish, or PowerShell:

```sh
actionlint -completion bash
```

The command writes the script to standard output, ready to load or install using your shell's completion setup. `auto` selects a shell from the environment, and `-completions` is accepted as an alias. Thanks @Freed-Wu (rhysd/actionlint#716, rhysd/actionlint#300; kjanat/actionlint#45).

The new `actionlint-shellcheck` pre-commit hook installs the Go-distributed ShellCheck dependency alongside actionlint, so a configured hook environment includes both checks. Thanks @kadykov (rhysd/actionlint#482; kjanat/actionlint#31).

## Other compatibility and maintenance improvements

- Accept `copilot-requests` and `drives` permission scopes. Thanks @v1v for `copilot-requests` (rhysd/actionlint#689; kjanat/actionlint#28).
- Accept a plus sign and leading zeros in expression exponents. Thanks @semx for the exponent-sign fix (rhysd/actionlint#708; kjanat/actionlint#29).
- Reject `$/` references that contain no path (kjanat/actionlint#30).
- Include all expected `workflow_dispatch` input keys in unexpected-key diagnostics. Thanks @Socialpranker (rhysd/actionlint#715; kjanat/actionlint#25).
- Let `**` match any property name in untrusted-input maps. Thanks @hugo-syn (rhysd/actionlint#332, rhysd/actionlint#345; kjanat/actionlint#37).
- Add OCI source and license labels so container metadata identifies this repository. Thanks @nozomiishii (rhysd/actionlint#653; kjanat/actionlint#26).
- Add a hosted expression conformance probe to compare parser behavior with GitHub Actions itself (kjanat/actionlint#35).

Upgrade for the new correctness checks; enable policies separately when your repository is ready to enforce them. See the [configuration documentation for v1.13.0](https://github.com/kjanat/actionlint/blob/v1.13.0/docs/config.md).

v1.9.0 expands support for GitHub Actions workflows that use background work, parallel steps, and self-repository references. It also updates expression contexts, permission names, events, and the built-in action metadata so newer workflows can be checked without unnecessary suppressions.

## Check background and parallel work

actionlint now understands `background`, `wait`, `wait-all`, `cancel`, and `parallel` steps. A background step can run while later steps do independent work:

```yaml
on: push
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - id: prepare
        run: echo preparing
        background: true
      - run: echo independent work
      - wait: prepare
```

The checker verifies that a `wait` or `cancel` target names an earlier background step. Changing the last line to `wait: preapre` produces a useful reference error. It also checks the shape of `parallel` groups and rejects invalid nesting, so accepting the new syntax does not mean accepting every arrangement of steps.

Thanks @devantler for rhysd/actionlint#695.

## Resolve self-repository actions and reusable workflows

References beginning with `$/` are now understood. For example:

```yaml
steps:
  - uses: $/.github/actions/greet
    with:
      name: World
```

When the referenced files are available locally, actionlint reads their metadata and checks inputs and outputs. This covers both actions and reusable workflows, so a self-repository reference retains the checks you expect from a local reference. Related: rhysd/actionlint#711.

## Use current permission names and expression contexts

The permission checker supports `code-quality` and `vulnerability-alerts` with their accepted access levels, and recognizes `models` and `repository-projects`. Thanks @smlx for rhysd/actionlint#674 and @kalverra for rhysd/actionlint#714.

Expressions can now use `job.workflow_file_path`, `job.workflow_ref`, `job.workflow_repository`, and `job.workflow_sha`, along with `jobs.<job_id>.result` where the `jobs` context is available. This removes false unknown-property errors for workflow identity and reusable-workflow result expressions. Thanks @nikolauspschuetz (rhysd/actionlint#696), @alexchen-sys (rhysd/actionlint#707), and @Eljees (rhysd/actionlint#724).

## Fewer false errors in reusable workflows

A workflow that declares `workflow_call` alongside another trigger can still use repository secrets for its other entry points. actionlint no longer incorrectly treats every such secret as an undeclared reusable-workflow input. Thanks @Eljees for rhysd/actionlint#701 and rhysd/actionlint#703.

The generated webhook data also accepts the `destroyed` activity type for `merge_group`, covering cleanup workflows for merge groups that are removed. Related: rhysd/actionlint#726.

## Refresh popular action metadata

The built-in database now includes newer major releases such as `actions/checkout@v7`, `actions/cache@v6`, `actions/setup-go@v7`, and `codecov/codecov-action@v7`. Updating the data keeps input and output checks useful when you update the actions in your own workflow. This refresh builds on rhysd/actionlint#718; thanks @kolyshkin.

## Immutable release assets

This release is protected by release immutability. The `v1.9.0` tag is locked to its commit, and its attached assets cannot be replaced or removed. Pinning this release gives you the same published files; corrections to those files require a new release.

Release titles and notes remain editable. See [GitHub's immutable release documentation](https://docs.github.com/en/code-security/concepts/supply-chain-security/immutable-releases) for the protections this provides.

Upgrade to this release when adopting the newer step forms or `$/` references, or when older metadata is producing false errors for current actions and contexts.

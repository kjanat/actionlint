v1.15.0 makes the fork easier to install and configure. It adds editor assistance for the configuration file, publishes the command through npm and more package managers, restores Go 1.26 source compatibility, and improves Homebrew completions and documentation.

## Get editor help when creating configuration

Run:

```sh
actionlint -init-config
```

The generated `.github/actionlint.yaml` now starts with a YAML Language Server directive:

```yaml
# yaml-language-server: $schema=https://raw.githubusercontent.com/kjanat/actionlint/HEAD/actionlint.schema.json
```

Editors that support it can offer completion, hover documentation, and schema validation for actionlint's configuration. The schema is generated from the Go configuration types, reducing the risk of editor suggestions drifting from the program.

Schema validation and runtime parsing have some documented differences, so the linter remains the final check for a configuration's behavior. The schema is hosted in the repository in this release; including it in the npm package follows in v1.16.0. Related: kjanat/actionlint#120.

## Run a prebuilt binary through npm

The [npm package](https://www.npmjs.com/package/@kjanat/actionlint) now provides the command:

```sh
npx @kjanat/actionlint@1.15.0 --help
```

The launcher selects a matching prebuilt binary from eleven platform packages across macOS, Linux, Windows, and FreeBSD. It also includes the command manual. Using these packages does not require compiling actionlint with Go. ShellCheck and pyflakes remain optional external integrations.

Publishing runs as a reusable workflow after the release binaries have been uploaded, attested, and checked. This avoids relying on a `release: published` event that GitHub suppresses when the release was created with `GITHUB_TOKEN`. Packaging dry runs can use an existing release's assets. Related: kjanat/actionlint#95 and kjanat/actionlint#123.

## Install through the fork's own package identities

Release automation now updates the [Scoop bucket](https://github.com/kjanat/scoop-bucket), the AUR packages [actionlint-kjanat](https://aur.archlinux.org/packages/actionlint-kjanat) and [actionlint-kjanat-bin](https://aur.archlinux.org/packages/actionlint-kjanat-bin), and WinGet submissions under `kjanat.actionlint`. The [actionlint-kjanat-git](https://aur.archlinux.org/packages/actionlint-kjanat-git) AUR package builds from the default branch.

These names distinguish the fork from packages that still install upstream actionlint. WinGet publication requires review; the initial submission is microsoft/winget-pkgs#430563, so an automated submission alone does not mean `winget install` is available. Related: kjanat/actionlint#96, kjanat/actionlint#97, and kjanat/actionlint#98.

## Use the shared Homebrew tap and generated completions

The canonical Homebrew installation is now:

```sh
brew install --cask kjanat/tap/actionlint
```

The cask includes the manpage and generates Bash, Fish, Zsh, and PowerShell completions from the installed executable. Thanks @muzimuzhi for kjanat/actionlint#113.

Publishing targets [kjanat/homebrew-tap](https://github.com/kjanat/homebrew-tap). The former [kjanat/homebrew-actionlint](https://github.com/kjanat/homebrew-actionlint) tap redirects through migration metadata. ShellCheck is optional and can be installed separately from `kjanat/tap/shellcheck`. Related: kjanat/actionlint#121.

## Build with Go 1.26 again

Source builds and `go install` work with Go 1.26 again after v1.14.0 raised the minimum to Go 1.27. The preferred development toolchain remains Go 1.27.1. This restores compatibility for consumers whose build environment is staying on Go 1.26. Related: kjanat/actionlint#111.

## Clearer documentation and release upkeep

The manual and installation guide now cover the current flags, configuration, output formats, completions, and package availability. The guide documents mise's `github:kjanat/actionlint` backend and identifies integrations that still install upstream packages. The README, docs, and Playground link to the GitHub Actions changelog reader. Related: kjanat/actionlint#123.

Release workflow references to `kjanat/runner` and `vedantmgoyal9/winget-releaser` are pinned to commit SHAs. Thanks @sethbacon for the report in kjanat/actionlint#115; the fix is kjanat/actionlint#118.

The README's fork/upstream comparison now identifies both measured versions. Upkeep refreshes it after releases and weekly, opening a PR when results change. Generated-table and go-shellcheck updates also use separate Upkeep PRs, so normal CI no longer fails merely because a new release changes a live comparison. The changelog monitor installs its dependencies separately from the npm workspace, and the bump tool covers the new packaging examples.

Upgrade for editor-assisted configuration, the new distribution routes, or restored Go 1.26 support. See the [installation guide for this release](https://github.com/kjanat/actionlint/blob/v1.15.0/docs/install.md).

v1.14.0 makes successful GitHub Action runs easier to understand and released containers easier to identify and verify. It also corrects GitHub context types and adds the site's GitHub Actions changelog reader. Source builders should note the Go 1.27 requirement introduced in this release.

## See what a successful action run checked

The Docker action now logs the actionlint version, problem count, workflow-file count, and enabled external linters. A successful run that inspected no workflow files is visibly different from a clean run that actually checked them.

This makes it easier to spot a wrong working directory or file selection without having to create an artificial lint error. The documentation also clarifies the runtime requirement: the action needs a reachable Docker daemon. `ubuntu-slim` cannot run it merely because a Docker client is installed; daemon-less runners can download and run the binary. Standard ARM Ubuntu runners are supported. Related: kjanat/actionlint#56 and kjanat/actionlint#87.

## Read the fork and installation source from `-version`

The release binary reports:

```text
actionlint.kjanat.dev 1.14.0
https://github.com/kjanat/actionlint/releases/tag/v1.14.0
```

The first line now identifies the fork as well as the version. Scripts that previously expected only a bare version number on that line need to account for the prefix. The following line identifies the installation source, with concise values for source builds, `go install`, Docker images, or release downloads.

Local `make build` builds are stamped with `git describe --tags`, so a development checkout can identify its distance from a release instead of reporting an unhelpful development or pseudo-version. Related: kjanat/actionlint#66.

## Correct artifact and retention expressions

`github.artifacts` and `github.artifacts_list` are recognized as string-valued command-file paths. `github.retention_days` is also typed as a string, matching the value provided by GitHub Actions.

Convert it when a numeric expression is needed:

```yaml
on: push
jobs:
  report:
    runs-on: ubuntu-latest
    steps:
      - run: echo retention exceeds seven days
        if: ${{ fromJSON(github.retention_days) > 7 }}
```

These corrections remove unknown-property errors for the artifact paths and avoid misleading type assumptions about retention. The context updates are part of kjanat/actionlint#105.

## Verify release images and inspect their contents

Container releases now carry SBOM attestations, explicit provenance, and OCI labels and annotations. Both the CLI and action images are smoke-tested before publication. Their image digests receive GitHub build-provenance attestations, and binary release archives have accompanying SPDX SBOM files generated with Syft.

For example, verify the CLI image for this release with:

```sh
gh attestation verify oci://ghcr.io/kjanat/actionlint:1.14.0 --repo kjanat/actionlint
```

The CLI images also gain major and minor moving aliases, such as `1` and `1.14`, alongside the exact version and `latest`. The aliases advance only for the newest release in their respective line. Related: kjanat/actionlint#80.

The moving Git action tag points to a separate commit whose `action.yml` pins the published action image by digest. Resolving that commit gives you an action definition tied to those image bytes. The moving tag itself can still advance, while `v1.14.0` remains on the release commit and its action definition uses the release image tag. Related: kjanat/actionlint#85.

SARIF output now identifies this fork in its tool and rule-documentation links. The documented CLI format and Docker action use a shared template, keeping reports consistent between the two entry points.

## Read GitHub Actions announcements alongside the Playground

The [GitHub Actions changelog reader](https://actionlint.kjanat.dev/github-changelog/) arrives in this release. It provides a searchable view of the Actions changelog feed, article content, type filtering, and access to the original feed data. A repository monitor tracks new announcements so changes in GitHub's workflow syntax and runner behavior can be investigated. Related: kjanat/actionlint#103.

## Source-build and maintenance changes

This release raises the source-build minimum to Go 1.27. The downloadable binaries do not require a local Go installation. **Go 1.26 compatibility is restored in v1.15.0**, so consumers staying on Go 1.26 should choose that later release or newer. Related: kjanat/actionlint#106.

CI covers the current Linux, macOS, and Windows x64/ARM64 runners, checks generated tables, and builds a release snapshot with SBOMs. The bump tool now moves `Unreleased` entries into a dated changelog section automatically, keeping the version commit and its release history together.

Upgrade for clearer action logs, corrected context types, and richer release verification. Account for the `-version` output change if a script parses it.

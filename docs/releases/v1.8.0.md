v1.8.0 is the first release of this fork after upstream v1.7.12. It brings newer GitHub Actions syntax and runner images into the checker, and fixes a ShellCheck integration hang that could prevent linting from finishing.

## Use concurrency queues without false syntax errors

Workflows and jobs can now use `queue` in their concurrency configuration:

```yaml
on: push
concurrency:
  group: release
  queue: max
  cancel-in-progress: false
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - run: echo ready
```

actionlint accepts `single` and `max`, checks invalid values, and reports the contradictory combination of `queue: max` with `cancel-in-progress: true`. You can check a workflow using the queue feature locally without suppressing an unknown-key error and losing useful validation around it.

Thanks @vvoland for the work and reports in rhysd/actionlint#654 and rhysd/actionlint#657. See [GitHub's concurrency syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#concurrency).

## Recognize newer runner images and aliases

The runner checks now accept `ubuntu-26.04`, `ubuntu-26.04-arm`, `xcode-27`, `xcode-27-xlarge`, and `windows-11-vs2026-arm`. Thanks @ericcornelissen for rhysd/actionlint#683 and @TheAlphaEngineerCode for rhysd/actionlint#710.

Alias compatibility follows the image migrations recorded for this release: `macos-latest` maps to `macos-26`, `macos-latest-large` to `macos-26-large`, and `windows-latest` and `windows-2025` to `windows-2025-vs2026`. This matters when checking whether several runner labels describe a compatible image. Sources: actions/runner-images#14167 and actions/runner-images#14017.

## Customize service startup

Service containers can declare their own `entrypoint` and `command`. For example, a service can select a different startup command without being rejected by the workflow parser:

```yaml
services:
  cache:
    image: redis:7
    entrypoint: redis-server
    command: --appendonly yes
```

This is particularly useful for integration tests that need a service configured differently from its image defaults. Thanks @mkusaka for rhysd/actionlint#645.

## Finish large ShellCheck runs on Linux and macOS

ShellCheck now starts before actionlint streams the script to it. Previously, writing the script into the stdin pipe before starting ShellCheck could fill the pipe and block linting indefinitely. The bug was reproduced on both macOS and Linux, and a single sufficiently large `run:` step could trigger it without concurrent steps.

Thanks @attehuhtakangas for the fix in rhysd/actionlint#651, and @kjanat for [the Linux reproduction](https://github.com/rhysd/actionlint/pull/651#issuecomment-5217723922) confirming that the problem was not limited to macOS or concurrent runs.

The YAML dependency was also updated to go-yaml v4.0.0-rc.6. YAML parse errors have corrected columns, including source positions for undefined aliases, so the reported location is more useful when fixing malformed files.

## Release and contributor changes

This release establishes binary publication from `kjanat/actionlint` and multi-platform CLI images at `ghcr.io/kjanat/actionlint`. Homebrew and WinGet publication were not enabled at this point. CI was adjusted for the Windows ARM64 runner and current hadolint images, including ShellCheck installation through Chocolatey and a numeric guest UID in the container image. Go dependencies were refreshed alongside the YAML update.

If you use the older upstream release and need the queue syntax, service startup options, or these runner labels, this is the first fork release that checks them. For installation today, follow the [current installation guide](https://github.com/kjanat/actionlint/blob/master/docs/install.md).

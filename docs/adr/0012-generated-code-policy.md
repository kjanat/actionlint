# 0012 — Generated code is not committed, except the config schema

Status: accepted · 2026-10-27

## Context

v1 committed generated Go bindings, contract digests, and formatter-shaped
generated files. Naming conventions for them were argued about repeatedly
and generated headers were hand-edited. Reviews spent time on diffs nobody
wrote.

## Decision

- WIT bindings, Rust: host via `wasmtime::component::bindgen!`, guests via
  `wit_bindgen::generate!`, both compile-time macros. Nothing committed.
  [docs.rs/wasmtime `component::bindgen`, docs.rs/wit-bindgen `generate`]
- WIT bindings, C (test guest in `tests/guests/c-minimal`): `wit-bindgen c`
  emits `.c/.h/_component_type.o` files. Those are produced by the test
  build step (`xtask guests`) into `target/`, not committed. `wit-bindgen-cli`
  is documented as "NOT stable" — pin its exact version in `xtask`.
  [github.com/bytecodealliance/wit-bindgen README]
- tree-sitter parser: the grammar crate ships its own generated `parser.c`.
  This repo never vendors it.
- Config schema: `actionlint.schema.json`, generated by `xtask schema`,
  committed, CI diff-checked (ADR-0010). It is the single exception because
  editors fetch it by URL.
- Rule docs: rendered by `xtask rules-doc` into `target/`, published by the
  docs pipeline, not committed.
- Fixture expectations (`expected.json`) are test data, written by
  `xtask bless` and reviewed as code. They are not "generated code".

## Consequences

- No `*.gen.rs`, no `// Code generated` headers, no committed `OUT_DIR`
  copies.
- `cargo build` must succeed from a clean clone with only `rustc` and a
  C compiler.

## Open

- None.

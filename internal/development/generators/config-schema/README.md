# Configuration schemas

Run `mise run generate:config-schema` from the repository root to update `actionlint.schema.json`. A test compares the generated bytes with the committed schema.

`tools` has one entry per provider manifest under `internal/model/bundledproviders`. The `config_schema` of each manifest describes the inline `config` settings, and its `config_shorthands` appear beside the host keys. The host keys alone describe any other tool name. When a `config_schema` equals a snapshot under `schemas/<name>/`, the root schema references the snapshot with a relative `$ref`, as for `schemas/shellcheck/0.11.0.schema.json`. The root schema embeds every other `config_schema`.

The schemas omit `$id`. Each `$ref` resolves against the location of its schema.

Rule-specific options use `allOf` beside the shared settings. `actionlint config schema` applies the same definitions to installed plugin rules and adds their names to the completion list.

Rule selectors reference `rule-name`. Its `known-rule-name` branch supplies completions, and a nonempty string branch accepts plugin rule names. Configuration loading validates the names against registered rules. A deprecated alias gets a `const` branch with `deprecated: true` and a description that names its replacement.

Tombi reads `x-tombi-toml-version` to select TOML 1.1 and `deprecationMessage` to name the replacement of a deprecated alias. See [Tombi's schema extensions](https://tombi-toml.github.io/tombi/docs/json-schema/).

`ruleconfig.Levels()`, `Presets()` and `Categories()` supply the accepted value sets. Do not add another list.

## Updating tool settings

When the settings of a tool change, update its `config_schema` and regenerate the root schema. `TestBundledProviderSchemas` checks that the generated settings match.

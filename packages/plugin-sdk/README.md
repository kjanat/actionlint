# @kjanat/actionlint-plugin-sdk

Author TypeScript process providers for actionlint. Requires Node.js 22.18 or newer. The SDK ships ESM JavaScript and declaration files. Its CLI uses esbuild to bundle author TypeScript and dependencies into the installed process executable.

This SDK is not published on npm yet. For local development, install it with a `file:` dependency. Run `actionlint-plugin init` in a new package, implement the exported provider, install dependencies, then run `actionlint-plugin pack`. The command writes `actionlint-provider.json` with registry metadata embedded, bundles the TypeScript check into `actionlint.js`, and adds the `./actionlint` package export. It preserves existing exports and adds the generated files to an explicit npm `files` list. Install the plugin package into the consuming Node project so actionlint can resolve the package export from that project's working directory; the generated npm bin is only a convenience alias. Packing does not publish or create a registry release asset.

`defineScriptProvider` accepts a TypeScript diagnostic callback. Its executable reads one JSON request from stdin (`source`, `filename`, optional `config`) and writes one response. `serveScriptEngine` validates untrusted JSON, bounds input/output, catches callback errors into the response envelope, and keeps stdout reserved for protocol data. Do not log to stdout. Columns count Unicode scalar values; rows are one-based LF lines and end locations are exclusive. Snippet source is data and is never evaluated. Packing uses esbuild to bundle author code and its dependencies for Node.js 22; list packages that must remain external in `external` and install those packages with the plugin.

`defineProcessProvider` describes an existing PATH tool. Use `jqOutput("./transform.jq")` to inline output transformation source during `pack`, avoiding a hand-computed digest. Repository-selected native processes require `actionlint --allow-config-processes`. An explicitly invoked registry plugin uses `--plugin`; a process selected from repository configuration requires `--allow-config-processes`. Their child process still runs with the host's process policy; this SDK does not sandbox native code.
